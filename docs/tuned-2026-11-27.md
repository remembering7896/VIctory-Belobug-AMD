# Tuned run: what was measured (2026-11-27)

One PC: Ryzen 7 9800X3D, 32 GB RAM, Radeon RX 7900 XTX 24 GB, Windows 11
build 26300, Series X profile at 1080p output, ray tracing off. Builds are
`cargo build --locked --profile diag -p victory --features diagnostics`.
Every run is the same sequence from a cold start, 6-10 minutes, and the
figures are of the `host: … fps, … ms/frame` line the runtime prints.

Scenes are not identical between runs; read differences under about 5 % as
nothing. The numbers below repeat across runs, which is why they are kept.

## Where the time went

| Build and settings | p50 frame | p50 fps | p90 frame |
|---|---|---|---|
| original tree, default switches | 59.0 ms | 17.0 | 103.3 ms |
| + the memory patches of this branch | 58.3 ms | 17.4 | 72.5 ms |
| + the renderer port switches (below) | **46.2 ms** | **21.9** | 86.6 ms |

The port switches are the ones `README.md` lists as off by default while
they are tested. Turning them on is worth about 15 ms a frame, more than
every memory patch in this branch together. In the log the preparing
thread goes from 42-52 ms to 28.9 ms a frame: `VICTORY_PORT_CBV` removes
about 22,000 constant-buffer fills a frame, `VICTORY_PORT_GUARD` takes the
title threads' guard waits from 29 ms to about 2 ms, `VICTORY_PORT_JOURNAL`
takes the submit thread's waits from about 6 ms to 0.3 ms.

`scripts/run-tuned.bat` starts the title with them on.

## What was tried and refused

Each was applied on top of the winning tree, built, and run the same way.
All three are worse here, whatever they win elsewhere:

| Change | p50 frame | p50 fps |
|---|---|---|
| Belobug #443 + #451 (exact/loose lock contention) + #393 (tiled mip row runs) | 53.8 ms | 18.6 |
| Belobug #394 (32 GB switch set) + avatarmanz #391 (`VICTORY_WINDOWS_BAR_PCT`) | 51.5 ms | 19.4 |

A first attempt that also carried #393 and #374 in the same commit as the
eleven memory patches measured 8-15 fps; both were dropped, and the
patches are only added to the tree after a run in this table.

## 60 Hz

`VICTORY_FRAME_INTERVAL_MS=16.667` does what it says: the menus and videos
reach 55-60 fps (best frame 16.7 ms) and the log confirms the clock is
adjusted (`our clock 16.667 ms; the title's rate 60 … it asks for 16667 us
at 60 Hz`). In the world it costs about 9 ms a frame (median 55.4 ms
instead of 46.2), because twice as many submissions queue on the one
submitting thread. Not used by `scripts/run-tuned.bat`.

## Memory

The eleven patches in this branch reclaim idle upload memory and cap the
texture store; on this 32 GB PC the peak private bytes went from about
38 GB to about 36-37 GB, and the p10 frame improved from 9.7 to 13.8 fps
(fewer long stalls). The pressure thresholds these checks use are only
reached when the machine is short of RAM, so a 32 GB box shows much less
of the effect than the 16 GB reports in the pull requests.

The eleven, all from `Belobug/VIctory-Belobug-AMD` with `base=a-publier`:
#386, #404, #373, #372, #375, #359, #287, #409, #413, #401, #407.
